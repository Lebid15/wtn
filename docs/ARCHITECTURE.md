# معمارية النظام — Architecture

> نظام لوحة وكلاء لشحن الألعاب (عربي / سوريا)
> المرجع الوظيفي: `reference/FEATURE_MAP.md`

---

## 1. نظرة عامة

نظام **متعدد المستأجرين (Multi-Tenant SaaS)**. أنت (الشركة) تملك المنصّة
وتبيع نسخاً لوكلاء آخرين، كل وكيل يحصل على لوحته الخاصة بنطاق فرعي.

### هرم الأدوار (Roles Hierarchy)

```
┌─────────────────────────────────────────────────────────────┐
│  PLATFORM OWNER (أنت / الشركة)  ← لوحة السوبر أدمن           │
│  • إدارة المستأجرين (Tenants) وبيع الاشتراكات                │
│  • الكتالوج المركزي للألعاب (Global Catalog)                 │
│  • مراقبة النظام والفوترة                                     │
└───────────────┬─────────────────────────────────────────────┘
                │ يبيع نسخة لكل مستأجر
        ┌───────▼────────┐   ┌────────────────┐
        │  TENANT (وكيل   │   │  TENANT آخر     │  ← لوحة إدارة المستأجر
        │  اشترى النظام)  │   │  (نطاق فرعي)     │    (هذه هي اللوحة الكبيرة
        │  bayi.alaya.com │   │ bayi.barakat.com│     في FEATURE_MAP)
        └───────┬────────┘   └────────────────┘
                │ تحته وكلاء
      ┌─────────▼──────────┐
      │  ANA BAYI (وكيل رئيسي) → BAYI (وكيل) → ALT BAYI (وكيل فرعي) │
      └─────────┬──────────┘
                │ يبيعون للعملاء
        ┌───────▼────────┐
        │  CUSTOMER STORE (متجر العميل بنطاق الوكيل)              │
        └────────────────┘
```

> **ملاحظة مهمة:** الموقع المرجعي `bayi.alayatl.com` هو **لوحة مستأجر واحد**
> (alayatl اشترى النظام من الشركة التركية). فمعظم `FEATURE_MAP` يصف
> **لوحة المستأجر (Tenant Admin)** — وهي جوهر النظام وأكبر جزء من القيمة.
> لوحة السوبر أدمن (أنت) أخفّ: إدارة المستأجرين + الكتالوج + الفوترة.

## 2. المكوّنات (Applications)

المشروع **Monorepo** يحتوي التطبيقات التالية:

| التطبيق | الوصف | المستخدم |
|---------|-------|----------|
| `backend/` | API + منطق العمل + قاعدة البيانات + الطوابير | (خدمة) |
| `frontend/superadmin/` | لوحة مالك المنصّة | أنت |
| `frontend/tenant/` | لوحة إدارة المستأجر (OyunPin/Ayarlar/Raporlar) | الوكيل المشترك |
| `frontend/store/` | متجر العميل النهائي | زبائن الوكيل |

> يمكن دمج `superadmin` و `tenant` في تطبيق Next.js واحد بمسارات مختلفة إذا
> فضّلنا التبسيط لاحقاً. نبدأ بالفصل المنطقي.

## 3. الحزمة التقنية (Tech Stack) — مقترحة

| الطبقة | التقنية | السبب |
|--------|---------|-------|
| Backend | **NestJS (TypeScript)** | بنية منظّمة، مناسبة لمنطق عمل معقّد |
| ORM | **Prisma** | مخطط واضح، migrations آمنة |
| قاعدة البيانات | **PostgreSQL** | معاملات مالية موثوقة (ACID) للمحفظة |
| الطوابير | **Redis + BullMQ** | تنفيذ الطلبات، تحديث الأسعار المجدول |
| Frontend | **Next.js + TypeScript** | نفس اللغة، أداء جيد |
| التنسيق | **Tailwind CSS** | سريع، بأبعاد ثابتة (انظر §5) |
| المصادقة | **JWT + TOTP (2FA)** | بديل حديث لآلة حاسبة المرجع |

> **هذه توصية — قابلة للتغيير.** لو عندك تفضيل آخر (مثلاً Laravel/PHP قريب
> من المرجع الأصلي)، أخبرني قبل ما نبدأ كود.

## 4. تعدد المستأجرين (Multi-Tenancy)

**النموذج:** قاعدة بيانات واحدة مشتركة + عمود `tenant_id` في كل جدول
(Row-Level Isolation). أبسط وأرخص للتوسّع وبيع نسخ كثيرة.

- **حلّ النطاق (Subdomain resolution):** middleware يقرأ النطاق الفرعي
  (`bayi.alaya.com`) → يحدّد `tenant_id` → كل الاستعلامات تُفلتر تلقائياً به.
- **العزل:** كل استعلام Prisma يمرّ عبر طبقة تفرض `tenant_id` — لا يرى مستأجر
  بيانات مستأجر آخر إطلاقاً.
- **الكتالوج المركزي (Global):** جداول على مستوى المنصّة (قائمة الألعاب الأم)
  بدون `tenant_id`، والمستأجرون "يتبنّون" منها.

## 5. قرار التصميم: واجهة غير متجاوبة (Non-Responsive) ⭐

**متطلّب أساسي من المالك:** التصميم بعرض كمبيوتر **ثابت** — في الجوال يظهر
نفس تخطيط الكمبيوتر كاملاً بحجم مصغّر، والمستخدم يكبّر بأصابعه (pinch-zoom)
ويضغط أينما أراد. **لا breakpoints ولا تكيّف مع حجم الشاشة.**

### التطبيق التقني:
1. **Viewport ثابت** في `<head>` بدل `device-width`:
   ```html
   <meta name="viewport" content="width=1600, user-scalable=yes">
   ```
   هذا يجعل الجوال يعرض الصفحة بعرض 1600px مصغّرة، ويسمح بالتكبير.
2. **حاوية بعرض ثابت:** `.app { width: 1600px; margin: 0 auto; }`
3. **ممنوع** استخدام responsive utilities (`sm: md: lg:`) في Tailwind — نضبط
   إعدادات Tailwind لتعطيل الـ breakpoints أو نتجاهلها.
4. **أبعاد بالبكسل الثابت** (px) للأعمدة والجداول والـ navbar — لا نِسَب مرنة
   تعتمد على عرض الشاشة.
5. **نفس الـ Navbar والأقسام** المطابقة للمرجع (12 أيقونة تنبيه + القوائم).

> النتيجة: تجربة مطابقة للمرجع تماماً على الكمبيوتر والجوال (مصغّر + zoom).

## 6. الطبقات داخل الـ Backend

```
backend/src/
 ├─ core/            (Auth, Tenancy, RBAC, i18n)
 ├─ wallet/          (الرصيد الموقّع + Ledger + المدفوعات)
 ├─ catalog/         (الألعاب، المنتجات، الفئات Küpür)
 ├─ pricing/         (مجموعات الأسعار، التسعير التلقائي، سعر الصرف)
 ├─ orders/          (Takip، آلة الحالات، التنفيذ)
 ├─ providers/       (مزوّدو API، التوجيه 3-مستويات، المطابقة)
 ├─ pool/            (بنك البينات Havuz)
 ├─ reports/         (التقارير + تصدير Excel)
 ├─ notifications/   (الشات، الإعلانات، التذاكر، SMS)
 └─ platform/        (السوبر أدمن: المستأجرون، الفوترة)
```

كل موديول: `controller` (API) + `service` (منطق) + `dto` (تحقّق) + وصول
لقاعدة البيانات عبر Prisma.

## 7. تدفّقات غير متزامنة (Async / Jobs)

عبر BullMQ (Redis):
- **تنفيذ الطلب التلقائي:** طلب → طابور → استدعاء API المزوّد → تحديث الحالة.
- **التوجيه بالبدائل (Fallback):** فشل API الرئيسي → جرّب Api 1 → Api 2.
- **تحديث الأسعار المجدول:** cron يسحب أسعار الشراء من الـ APIs ويحدّث Maliyet.
- **النسخ الاحتياطي للأسعار كل ساعة** (كما في المرجع).
- **الإشعارات الصوتية / تنبيهات الطلبات المعلّقة.**

## 8. الأمان

- تجزئة كلمات السر (Argon2/bcrypt).
- **2FA (TOTP)** بتطبيق مثل Google Authenticator — بديل عن آلة حاسبة المرجع.
- تقييد الدخول من خارج البلد (يقابل Ülke Ayarı / Google Doğrulama).
- إعادة تعيين كلمة السر عبر SMS بعد محاولات فاشلة.
- سجلّات تدقيق (Audit log) لكل حركة مالية وإدارية.
- عزل صارم بين المستأجرين على مستوى قاعدة البيانات.
